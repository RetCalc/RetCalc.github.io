The stack

A static site that does its thinking in the browser.

Pages are prerendered and served from a CDN. Every number on them is worked out on the visitor's own machine, by a calculation engine that runs off the main thread. Accounts, when someone wants one, only hold their saved inputs.

The calculation engine

About 5,700 lines of finance, and a test for every claim.

One engine serves every page: projections, Monte Carlo, federal and state income tax, FICA, Social Security, RMDs, Roth conversions, ACA subsidies, Medicare and IRMAA, mortgages, debt, rent against buy, college, FIRE, the 72(t) bridge and historical withdrawal backtests.

The engine, by file (lines)
Three ways to ask "what if markets don't cooperate?"
Historical replayEvery starting month (or January) since 1926, run forward through what actually happened. The Drawdown Simulator's 30-year test has 835 of them.
Monte Carlo, calculators5,000 lognormal runs per redraw, set so the average matches the rate entered: with zero volatility it draws the plain projection exactly.
Monte Carlo, drawdownA block bootstrap of real history from 1927. Whole runs of consecutive years are drawn together, so the 1930s and 1970s keep their streaks.
Same seed, same chart

Every simulation shares one seeded random number generator (mulberry32), so a chart doesn't jump when an unrelated input changes. A Re-roll button moves the seed for all of them at once.

Off the main thread

A build step bundles the engine, its data and the Guide's planning jobs into one Web Worker, so a 300,000-retirement Optimizer run doesn't freeze the page.

Hosting and delivery

Fast because there is almost nothing to serve.

RetCalc runs on Vercel and deploys from the main branch. Pages are prerendered when the site is built, the homepage's and tool list's own figures included, so a visit is a handful of static files and a JavaScript engine that does the rest.

PieceHow it is done
HostingVercel. Production builds from main; every branch gets its own preview. Before 5 October 2026 the site was a hand-built static site; it now lives on in a private archive for comparison.
RenderingPrerendered pages and articles. There are no API routes: all calculation happens in the browser, and the one thing the site's own server receives is error reports, stripped of inputs, which it passes on to Sentry.
Domainretcalc.app, with DNS on Cloudflare; www redirects to the bare domain.
AnalyticsCloudflare and Vercel Web Analytics: cookieless page counts, production only. No ads and no ad trackers.
EmailSign-in codes go out through Resend from the site's own domain. Mail to contact@retcalc.app is forwarded separately.
InstallableA web app manifest and icons, so it can be added to a phone's home screen, with a bottom tab bar there.
Error reports that can't leak a plan
  • Errors only: tracing, replay and debug code are compiled out
  • Production only
  • Addresses cut to the path, so the query and the # that holds a tool's inputs never leave the page
  • No console breadcrumbs, user details or local variables
  • Sent through the site's own route, so ad blockers don't drop them
Link previews, drawn for every page

Each page has its own 1200×630 card: a title, a line of text and one of about 21 illustration types. A development-only page draws them and a headless browser saves them as static images, so sharing a link to any tool shows that tool.

Accounts and privacy

Local first. An account is only a way to sync.

Everything works without signing in. A signed-in visitor gets the same site, with their household, saved scenarios and Guide kept in step across devices. Saving never waits on the network, and a sync never throws anything away.

What an account stores
  • Email, and a first name if given
  • The household: ages, retirement age, state, savings, monthly saving, income, spending
  • Saved scenarios, by tool
  • Guide answers and plan, and the Paycheck plan
  • When each was last changed
What it never stores
  • Numbers typed into a tool but not saved (they stay in the tab, and survive a reload)
  • Browsing activity
  • Anything for advertisers: there are none, and no data is sold or shared
  • Share-link inputs, which ride after the # and never reach a server
Signing in, and out for good
  • A 6-digit code by email, or Continue with Google (whose script loads only when the sign-in box opens)
  • Download everything, any time
  • Delete the account: every session is signed out first, then the account and its synced data are deleted. It can't be undone
Signing in, as it looks on the site.

No password to remember: a code by email, or Google. The dialog says up front that an account is optional and that data is never sold or shared.

The privacy page names every service that touches data (Supabase, Google, Resend, Vercel, Cloudflare and Sentry) and what each one sees. A dedicated test script checks the row-level security rules.

Where the numbers come from

22 figures, each with a source and a due date.

Tax rules, Medicare and ACA prices, market history and sensible defaults all go stale. Each one is tracked in a list with its source, how often it changes, when it was last updated and when it is next due. Anything coming due is flagged at the start of every working session.

The rules for every update
  • Figures are never invented. Each is cited in a comment beside it.
  • A new tax year is added beside the old one, never over it. Income Tax lets you pick the year.
  • After an update the whole check suite runs, and every expected move is reviewed before baselines are re-recorded.
  • Articles are re-reviewed every 90 days and show the month.
